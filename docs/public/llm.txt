# 飞书 Playbook

> 用飞书搭建个人与团队工作系统的中文实战手册。

这份 Playbook 面向个人开发者和小团队，整理飞书、Agent、Skill、CLI、MCP、OpenAPI、本地数据库和团队协作之间的组合方式。

## 飞书在工作系统中的位置

飞书适合作为工作操作层：多维表格承接对象、状态和队列；文档与知识库承接上下文、方案和正式成果；任务承接行动；日历承接时间承诺；消息与卡片承接提醒、确认、进度和结果；妙记承接会议输入。

高频原始数据、复杂事务、长期日志和模型缓存进入 SQLite、PostgreSQL 或对象存储；飞书同步候选、状态、证据和协作结果。

## 推荐工作流

- 每日工作简报：读取日历和未完成任务，整理当天安排和优先行动。
- 会议到行动：提取决策、待确认事项和行动项，确认后创建任务并更新项目。
- 日程安排助手：查询忙闲，返回候选时段，确认后创建日程并回读验证。
- 个人 CRM：记录互动、承诺、跟进计划和来源。
- 项目记忆：维护带引用的 Wiki，分开事实、推断和待确认事项。
- Markdown 发布：使用主源、映射文件、revision 和备份建立稳定同步。
- Coding Agent：把飞书群、项目话题和本地工作区连接起来。
- 事件机器人：用事件订阅处理妙记、消息、Base 状态和审批变化。

## 默认工作合同

```text
Read → Plan → Confirm → Write → Verify → Report
```

每次写操作读取真实资源，展示计划和影响范围，执行最小写入，回读 ID 与状态，并返回链接、变更摘要和待处理事项。

## Skill 工程

Skill 分为原子 Skill、工作流 Skill、策略 Skill、调度与事件 Skill。可靠的 Skill 拥有明确的触发条件、输入、权限、读取集合、计划、确认策略、执行步骤、验证、幂等键、错误类型、输出和测试。

## 数据模型

推荐从四张表开始：

- `Projects`：项目状态、目标、下一步行动、负责人和来源。
- `Actions`：行动项、负责人、截止日期、状态、来源 ID 和幂等键。
- `Signals`：信号来源、事件键、证据状态、相关性和选题状态。
- `Agent Runs`：Skill、触发者、读取范围、计划写入、实际写入、状态和 API 预算。

## 稳定运行准则

1. 从最小 Agent 开始。
2. 按对象拆分 Base。
3. 让数据库承接原始日志。
4. 让候选内容进入知识流程。
5. 为写操作设置幂等键。
6. 读取完整分页。
7. 使用稳定 ID 关联资源。
8. 写操作先展示计划。
9. 事件驱动按需运行。
10. 设置主源与冲突策略。
11. 为 Skill 准备边界测试。
12. 关注工作结果指标。

## 30 天落地计划

- 第 1 周：搭建 CLI、应用授权、Projects、Actions、Agent Runs 和每日简报。
- 第 2 周：完成会议到行动、日程安排、幂等键、写后验证和待确认视图。
- 第 3 周：建立项目 Wiki 或行业信号管道。
- 第 4 周：补齐备份、配额、测试、版本和恢复路径。
