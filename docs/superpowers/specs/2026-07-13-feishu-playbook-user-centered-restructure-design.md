# 飞书 Playbook 用户视角重构设计

## 目标

把现有单页手册重构成一份能从真实任务进入、同时保留开发深度的飞书使用指南。读者打开页面后，先找到自己的身份和当前问题，再沿着最短路径完成第一套工作流；CLI、MCP、OpenAPI、Skill、权限和配额放在需要时继续深入的位置。

## 默认读者顺序

1. 正在使用飞书，希望整理个人工作的普通用户；
2. 希望把 AI 接入飞书的个人开发者；
3. 正在搭建团队流程的管理员和效率负责人；
4. 正在开发机器人、Agent 与自动化服务的工程师。

## 资料核对结论

- 飞书官方 CLI 当前 npm 版本为 `1.0.68`，官方 README 列出 200+ 命令、18 个业务域和 26 个 Agent Skills；
- CLI 已覆盖原生 Markdown、Slides、审批、OKR、妙记、妙搭 Apps 等新能力；
- 多维表格的当前产品定位包括业务系统、AI 字段、AI 工作流节点、BI、集成和精细权限；
- 飞书 aily 同时提供个人智能伙伴和企业级 Agent 平台；
- 基础版当前支持 100 用户、单表 2,000 行、每月 200 次自动化运行，基础免费版 API 常规上限为每月 10,000 次；
- 飞书 AI 使用统一 AI 额度，覆盖知识问答、妙记、aily、多维表格 AI、文档 AI、妙搭及其他已发布 AI 功能。

## 结构方案

采用“任务入口 + 分层深入”的单页结构：

1. **先从你的任务进入**：按普通用户、个人开发者、团队负责人和 Agent 开发者给出阅读路线；
2. **15 分钟起步**：用一套最小配置完成每日简报或会议到行动；
3. **飞书能力地图**：解释消息、文档、Wiki、Base、任务、日历、妙记、AI、妙搭和开放平台各自承担什么；
4. **工具选择**：按内置能力、Base 自动化、aily、CLI、MCP、OpenAPI、官方插件逐级选择；
5. **核心工作流**：保留高价值场景，补充审批、OKR、妙记、原生 Markdown、妙搭应用等当前能力；
6. **搭建一套个人工作系统**：给出最小数据模型、视图、知识结构和运行记录；
7. **Agent 与 Skill 工程**：保留身份、确认、幂等、事件、分页和结构化错误等技术边界；
8. **团队上线与长期运行**：合并重复的安全、可靠性、成本、治理和检查清单；
9. **30 天路线与参考资料**：从第一套工作流走到可运营系统。

## 文案编辑合同

- 使用肯定、直接、具体的中文表达；
- 标题优先回答用户问题，减少抽象名词和模板化栏目；
- 每个场景围绕“你会得到什么、怎样开始、系统怎样流转、完成后看什么”展开；
- 保留事实、数字、命令、代码、链接、引用和安全边界；
- 用具体对象与动作替代“赋能、闭环、体系化、全方位”等空泛词；
- 合并同义段落和重复清单，让全文具备自然的长短句与阅读节奏；
- 技术边界写成正向操作规则，例如“高频原始数据进入数据库，Base 保留协作状态”。

## 交付范围

- 重写 `docs/index.md`；
- 更新 `scripts/sync-readme.mjs` 的简介、全景图和目录；
- 更新 `docs/public/llm.txt`；
- 运行 README 同步、构建、类型检查、链接与 AI 腔扫描；
- 提交、推送、部署，并验证正式域名和旧域名跳转。

## 验收标准

- 首页在首屏和第一屏内给出角色入口、快速开始和工具选择；
- 当前官方 CLI、AI、多维表格、妙搭、审批、OKR、妙记能力已纳入正文；
- 章节主线从“系统架构目录”转为“用户任务路径”；
- 重复的推荐配置、规则、指标和治理章节完成合并；
- 正文、README、llm.txt 的定位和结构保持一致；
- `pnpm check`、`git diff --check` 通过；
- 正式页面返回 `200` 并出现新首屏文案，旧域名保持 `301`。
